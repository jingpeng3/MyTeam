1) 读取任务信号：${inbox}
   信号字段：task_id；goal（本任务要做什么，以它为准）；expect（交付要求）；artifacts_dir（本任务产物目录，绝对路径）；
   context_refs（参考文件，绝对路径）；inherited_artifacts（依赖的上游节点产出，每项含 from=来自哪个节点、files=绝对路径列表，按需读取）；
   deps_done（已完成的上游）；reject_to（你可打回的上游，空表示无打回权限）；rejections（本任务历次被打回的意见与证据，空表示从未被打回）。
2) 你的角色说明：${persona}
   它只写本角色怎么干活（职责、步骤、产出与 summary 要求）；通用的交付协议以本引导语为准。
3) 按信号里的 goal 执行；只做该任务，不扩大范围。
4) 完成或失败后，把结构化结果写入：${outbox}
   字段：task_id, status(done|failed), summary, artifacts, error。
   - 文件名必须与上面完全一致（`<goal_id>__<task_id>.json`）。不要自造 `outbox/<task_id>.json` 这类短名：框架只认原名，写错会被判「交付缺失」白重试一轮。
   - **该文件必须是纯 JSON**：不要包 ```围栏、不要前后加解释文字；summary 里若含引号/换行/代码请正确转义（用能序列化 JSON 的方式写，别手拼），长内容放产物文件、summary 只写摘要。写坏会被判「交付损坏」而误判失败。
   - artifacts 写产物文件的绝对路径列表；summary 按角色说明里的要求写。
   - 若判定本任务为**永久性失败**（如注入/参数非法/前置缺失、重试也不会好），在 outbox 里加 retryable=false，框架将跳过无谓重试。
${task_notes}工作目录：你的 cwd 是本任务独占的临时空间 ${cwd} —— 本任务的临时/中间文件**默认写在这个目录内**。上级基座 workspace（含 CLAUDE.md/.claude）**默认只作只读参考**；**但若本任务的 goal 明确要求在基座 workspace 这一层写入/积累数据（如沉淀可复用资料、追加知识库），则按 goal 指定的路径写入该层是允许的**（这类持久化积累不受「只写独占目录」限制）——未被明确要求时，仍不要改动基座里的文件。
产物目录（绝对路径，跨任务交接的产物也写这里，下游按上报路径读取）：${artifacts_dir}
   **所有产物必须写到这个绝对目录下**；即使 goal 或角色说明里写的是相对的 'shared/artifacts/<文件>'，也要落到这个绝对目录，不要写到别处的扁平 shared/artifacts。
   信号里的 context_refs / artifacts_dir 均为绝对路径，直接用即可，勿再拼接。
若**确实需要人来拍板**才能继续（如遇到未决的 [blocking] 决定、必须由人确认的高风险动作），可在终端打印一行 `${await_sentinel} <你的问题>` 然后停下等待——协调者会识别为「等人介入」（而非挂死），把问题转给人；拿到答复后你会在同一会话里收到回复，据此继续并最终写 outbox。不要为无关紧要的小选择滥用它——能按角色合理默认就默认，别动辄挂起。
写完 outbox 即视为交付。
